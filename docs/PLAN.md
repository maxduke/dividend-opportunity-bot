## 第三轮：命令响应和任务管理 — 已实现

优先解决行情请求较慢时，其他用户的帮助、暂停等命令也排队的问题。独立 PR 交付。

- [x] 手动查询、添加规则、恢复监控及代理状态查询移入后台；最多 2 个同时执行、20 个排队和执行中的任务。
- [x] 提供阶段进度、`/task`、`/cancel` 和取消按钮；每位用户同时仅允许一个耗时任务。
- [x] 规则修改版本核对覆盖手动查询、恢复和定时评估，旧结果不能覆盖编辑、暂停或删除后的规则。
- [x] 取消后不继续保存或推送未完成结果，已完成结果保留；明确阻塞数据源调用无法靠协程取消强制终止。
- [x] 添加规则先计算后保存；任务异常释放名额，应用关闭取消并等待后台协程退出。
- [x] 277 项离线测试通过，涵盖真实 Telegram 更新分发、队列上限、取消、权限隔离、规则变更、增量迁移及线程迟到结果丢弃。

本轮 PR 的 CI、review 和合并状态以 GitHub 为准。
